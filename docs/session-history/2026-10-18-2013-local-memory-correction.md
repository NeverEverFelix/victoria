# Session: Correct a local persistent memory

- Date: 2026-10-18
- Time: 20:13 America/New_York
- Status: Completed
- Scope: Enable authenticated append-only correction of one current memory in local persistent mode and verify future replies use the corrected fact.

## Outcome

Local persistent mode now supports `PATCH /api/memories`. It appends a user-correction fact linked to the prior memory, keeps the original historical record, and uses the corrected preference in later personalization. Local correction is authenticated by the existing signed local chat session.

## Work Completed

- Enabled local `PATCH /api/memories` in [the memory collection route](../../app/api/memories/route.ts); local inspection and forget remain available.
- Extended [the agent personalization path](../../src/agent/victoria-agent.ts) to understand a structured preference value when its evidence is generated by a user correction.
- Added PostgreSQL integration coverage in [persistent chat tests](../../tests/integration/memory/postgres-persistent-chat.integration.test.ts) for linked append-only correction and later retrieval.
- Updated [environment documentation](../../docs/environments.md), [user story](../../docs/user-stories.md), [test plan](../../tests/test-plan.md), and [agent work queue](../../docs/agent-work-queue.md).

## Decisions

- Local memory controls now include inspect, single-fact forget, and correction through the existing signed chat session.
- No UI or login/session issuer was added. Hosted routes retain Supabase Auth.
- Memory correction appends a linked record; it does not rewrite the prior fact.
